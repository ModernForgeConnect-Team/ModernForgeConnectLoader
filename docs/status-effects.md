# Legacy status effects

MFCL maps the original numeric potion array to native effects by stable names. Vanilla IDs 1–23 map by their Minecraft names; adapters can supply explicit names and texture atlases. Other original potions are discovered from their FML source JAR and potion name. Unknown source identities and unsupported attributes produce mapping diagnostics.

Minecraft 1.20.1 owns effect durations, application/removal, networking, curative items and saved data. Original `isReady`, `performEffect`, instant-effect and attribute-amount callbacks retain their original behavior. Player actors and entity query mirrors expose the mapped native effects. Original potion items convert their effect IDs in both directions.

The TC4 4.2.3.5 fixture contains nine potion instances: `thaumcraft:fluxtaint`, `visexhaust`, `infvisexhaust`, `unhunger`, `warpward`, `deathgaze`, `blurredvision`, `sunscorned`, and `thaumarhia` (each in the `thaumcraft` namespace). Entries described for other TC4 versions are not synthesized. The adapted TC4 utility class retains the Java 17 reflection fix required to expand its original potion array.

TC4's death-gaze and food-cure event callbacks run against native players. Original per-instance curative lists are retained, including effects that milk cannot cure. The original warp-event check runs every 2000 native player ticks, respects `Config.wuss` and Warp Ward, and is skipped when an addon already forwards the original living-update event. Death gaze asks the host player's PvP/team rules rather than an absent legacy MinecraftServer. The generic player-NBT bridge now saves and restores permanent, sticky and temporary warp plus the event counter, using the original TC4 keys; login/research synchronization includes all three original warp packets.

Purifying-fluid collision callbacks enter the correct server knowledge scope. An unwarded player consumes a source block and receives the original warp-dependent duration; flowing blocks and already-warded players do not consume a source. Sanity-soap release preserves original duration, item consumption and cure probability, including the ward bonus. Release callbacks return their original packets/chat and persist the changed player state.

Four original potion screen filters run through native post-processing; their private shader copies are upgraded from GLSL 1.20 to 1.50 and do not replace native shader resources. Original misc-event packets also drive native heartbeat/vignette and timed fog feedback. Native fog uses a linear distance matching the old exponential fog's approximate visibility range; its curve is not pixel-identical to fixed-function OpenGL fog.

Effect sprites use 18×18 cells at `x = index % 8 * 18`, `y = 198 + index / 8 * 18` in the old inventory atlas. The 198-pixel offset applies to TC4's custom atlas as well as the vanilla inventory texture. Generated sprites go into the native `textures/mob_effect/` directory and are regenerated on startup. Restart the game after installing a new MFCL build.

Run the disposable TC4/Baubles fixture with `-PmfclPotionSmokeTest`, a prepared `-PlegacyRuntimeDir`, and an isolated `-PmfclRunDir`. The probe writes `logs/mfcl/potion-smoke.json` and `screenshots/potion-inventory.png`. Verify the report's `status`, individual assertions and rendered screenshot; Gradle's exit code alone is insufficient. The graphical regression includes save/reload and checks that exported sprites contain visible pixels.

The TC4-specific assertions consume vis from a native held wand (1100 raw vis normally, 1300 with Vis Exhaust II, 1500 with Infectious Vis Exhaust IV; the combined penalty uses the stronger potion). They exercise actual native player-tick events for interval/ward/wuss guards and a deterministically selected original warp potion event, real bath collision and native soap release, original client packets, and warp-data world reload. This is not an exhaustive AI/combat acceptance of every guardian/spider encounter selected by the original random event table.
