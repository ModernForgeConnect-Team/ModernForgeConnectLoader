## 本体与安装

原版有 **8 种材质**：稻草、木头、油脂、粘土、血肉、石头、铁卫、神秘。每种都测试普通与高级版本。

功能核心为 metadata `0..11`，共 **12 种**；metadata `100` 的空白核心是制作材料，原版交互明确排除其安装，不应计为第 13 种工作核心。

组合矩阵为 `8 材质 × 2 普通/高级 ×（无核心 + 12 功能核心）= 208`：

- 208 组均能生成、被铃铛绑定，且持续存活 240 个服务器 tick；AI 调度计数确实前进。
- 除砍伐、使用外，10 种核心的 160 组组合均正确消耗 1 个核心，并自主寻路返回偏移后的家位置。
- 砍伐、使用的 32 组安装均发生异常：核心编号已写入傀儡，但物品没有消耗，任务列表只初始化了一部分。不能将此状态计为安装成功。

这属于本体、安装与基础导航验证，不代表 192 个带核心组合的所有工作任务均已完整验收。任务场景以普通木头傀儡为代表；未逐一验证各材质的伤害、回血、防火、负重、全部升级和装饰组合，也未经过傀儡放置物品的全部放置分支。

## 共用桥接缺口

**聚集的物品复制**：旧实体查询得到的是原生掉落物的镜像。原版 AI 修改旧物品栈并将旧实体标记死亡，但 `LegacyWorlds.commitEntityMotion` 当前只提交速度、摔落距离和繁殖状态，缺少掉落物数量与移除的回写。因此镜像中的“捡走”没有删除真实掉落物。此缺口应在共用实体桥接中修复，并验证部分拾取、NBT、不可映射物品和物品守恒，不能仅针对某个傀儡核心补删除代码。

两次独立任务世界均复现：只有地面 4 钻石输入，60 秒后主箱已有 60 钻石，地上原物品仍为 4 钻石。

**收获的作物表示与成熟度丢失**：原生小麦未得到正确的旧版作物类表示，世界桥接退回普通方块代理；同时现代 `age` 没有映射为旧版 metadata。直接查询实测：成熟小麦在旧世界中是 `net.minecraft.block.Block`，metadata 为 `0`，原版 `CropUtils.isGrownCrop` 返回 `false`。需要同时检查没有对应 BlockItem 的原版方块表示和作物状态映射；不能只绕过收获核心的成熟检查。

**砍伐、使用的假玩家**：两种原版 AI 构造时均通过 Forge `FakePlayerFactory.get` 请求 `GameProfile(null, name)`。共用 `LegacyTiles.fakePlayer` 将空 UUID 直接传给 actor；`LegacyPlayerAttributes.initialize/pull` 继而按空 UUID 查询原生玩家属性。存在在线玩家时，原生 `getPlayerByUUID` 抛出空指针。核心编号在异常前已经写入，因此出现“显示装上但不干活、也不扣核心”的中间状态。修复位置应为共用假玩家身份处理，并检查初始化失败时的交互原子性。

假玩家异常与在线玩家是否存在有关。`golem-jobs` 的资源任务阶段移除了配置用玩家；其重载字段不能代表有玩家在线的重载结果。单独的 `golem-reload` 使用同样的真实安装与 NBT 信封恢复流程，保留注册玩家，专门检查这一差异。10 tick 的重载探针不用于判定任务是否完成。

实测带玩家重载时，其他 10 种核心的木头傀儡均存活，砍伐、使用的傀儡则在恢复原版 NBT 时抛出同一异常，被宿主移除。无玩家时这两种核心反而能够重新注册完整 AI，说明无玩家重载通过不能排除实际游玩时的故障。

## 聚集核心修复（2026-11-05）

**确实存在刷物品，且不需要特殊条件。** 只要聚集傀儡的范围内有一个旧世界能看到的地面物品，它就会反复“捡起”同一堆物品并放入家容器，地面物品始终不变，直到容器放满或物品 6000 tick 后自然消失。修复前探针观察 1500 tick：地面 3 钻石时主箱攒到 48 颗，两个傀儡共用 16 钻石时两个箱子攒到 200 颗。由此带来的“搬不干净”就是用户看到的无法正常搬运：物品永远搬不完，傀儡永远不停。

修复前还有三个相关现象：

- 选定目标后物品被移除或变少（玩家捡走、合并），傀儡仍按选定时的数量拿走：物品已被移除时凭空得到 4 钻石。
- 带拾取延迟的物品也会被立即拿走，包括 `setNeverPickUp` 的展示物品。
- 傀儡死亡时掉落携带物，地面原物品又还在，同样多出一份。

**原因。** 原版 `AIItemPickup` 在 `shouldExecute` 时保存查询到的 `EntityItem`，走到后才执行 `getEntityItem().stackSize -= amount`。这个对象是宿主掉落物的镜像，有两层缺口：`commitEntityMotion` 只提交速度、摔落距离和繁殖状态；提交列表每 tick 清空，保存了多个 tick 的镜像根本不在列表里。镜像不会运行 `onUpdate`，所以数量减到 0 也不会死亡。

**修复位置（共用桥接层，未针对核心写特例）：**

- `EntityHostTransformer` 给 `EntityItem.getEntityItem` 插入钩子，并给它增加转发原实现的 `isEntityAlive`。旧代码每 tick 接触被保存的镜像时，`LegacyWorlds.retainedDroppedItem` 用宿主当前状态刷新它，并把它加入本 tick 的提交列表。宿主物品已不存在时，镜像读作已死亡且数量为 0，拿不到东西。
- 每个存活的宿主物品只对应一个镜像（弱引用），AI 保存的对象与之后查询到的是同一个。
- `commitEntityMotion` 回写掉落物：死亡或数量不大于 0 则移除，数量、NBT 或物品变化则经 `applyTo` 写回，保留宿主自有标签。写回同样走 `afterCommit`，加入事务。
- 宿主的 `pickupDelay` 映射到旧字段 `delayBeforeCanPickup`。

原版 `AIPechItemEntityGoto`、`EntityTravelingTrunk` 和 `TileArcaneBore` 也以同样方式改动掉落物镜像，会一并受益，但本次没有针对它们单独验收。

### 收获核心修复

**原因。** `CropUtils.isGrownCrop` 靠作物方块类和 metadata 判断成熟，而 `HostBlockMapping` 给旧世界的信息是错的，有三处缺口：

- `read` 没有把成长状态转成 metadata。成熟的小麦、胡萝卜、马铃薯、下界疣和可可 metadata 全是 0，一律判定为未成熟。
- 小麦没有方块映射。旧键 `minecraft:wheat` 同时是物品，又不是 `BlockItem`，两条映射规则都跳过了它，于是退回普通的 `net.minecraft.block.Block`。
- `write` 不接受作物的非 0 metadata，原版改写作物成长状态（如催熟）时会抛异常。

西瓜、南瓜和仙人掌不靠 metadata 判断，修复前本来就能收获。

**修复。** 小麦加入方块映射；`read` 和 `write` 双向转换 `age` 与 metadata，可可的方向放在低 2 位、成长阶段放在高位，与 1.7.10 一致。修复前后，旧世界看到的成熟作物如下：

| 作物 | 修复前 方块类 / metadata / 判定成熟 | 修复后 方块类 / metadata / 判定成熟 |
| --- | --- | --- |
| 小麦 | `Block` / 0 / 否 | `BlockCrops` / 7 / 是 |
| 胡萝卜 | `BlockCarrot` / 0 / 否 | `BlockCarrot` / 7 / 是 |
| 马铃薯 | `BlockPotato` / 0 / 否 | `BlockPotato` / 7 / 是 |
| 下界疣 | `BlockNetherWart` / 0 / 否 | `BlockNetherWart` / 3 / 是 |
| 可可 | `BlockCocoa` / 0 / 否 | `BlockCocoa` / 10 / 是 |

小麦、下界疣和可可的 metadata 写回现在也能到达宿主，并保留可可的朝向。

这个修复改变的是所有原版代码看到的作物状态，不只是傀儡。修复后 `golem-gather`、`golem`、`harvest-drops`、`leaf-harvest` 为 `PASS`。

`gameplay` 仍是 `FAIL`，但与本修复无关：唯一失败的检查是 `lootStackRoundTrips`（水下呼吸药水往返后多出 `CustomPotionEffects`），在两次修复之前的提交 `7512f77` 上结果相同。

后续修复药水往返后重新运行：`lootStackRoundTrips` 的 388 个样本及宿主效果修改写回均通过；这次总结果仍为 `FAIL`，唯一失败项为 `hellbatTicks`（召唤蝙蝠未存活），其原因尚未查明。

**覆盖边界。** 这是各核心的代表性基础任务，不是完整玩法验收：

- 除垂钓用神秘傀儡外（上钩概率低，并放宽到最多观察 6000 tick），都只用普通木头傀儡，未覆盖升级和其他材质的工作差异。带升级的自动补种没有验证。
- 砍伐只测橡木，使用只测右键放种子，未测左键和空手。收获未测甘蔗、魔力豆荚和可点击作物。
- 瓜类茎的 `age` 仍未映射（metadata 为 0）。原版收获逻辑会排除茎，所以不影响本核心，但读取茎成长状态的其他原版代码仍会读到 0。
- 守卫和屠夫的目标关闭了 AI，不会反击或移动。
- 只在专用服务器验证，没有在图形客户端观察动画、配置界面和标记显示，也没有单独验证生长之灯等其他依赖作物 metadata 的原版功能。

  '-PmfclValidationBuildDir=build/golem-audit-validation' `
  runServer '-PmfclRunDir=build/golem-audit-game' `
