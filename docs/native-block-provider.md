# Native block implementations

`github.com.gengyoubo.mfcl.api.spi.LegacyBlockProvider` is an optional SPI in 0.2.11-dev2. An addon registers its provider with `LegacyBlockProviders.register(provider)` from its mod constructor. Packaged providers may also use `META-INF/services/github.com.gengyoubo.mfcl.api.spi.LegacyBlockProvider`; explicit registration works with development source-set resources too. Providers are deduplicated by implementation class. MFCL calls them in the host block registration window, after original declarations have been captured. A provider returns null for keys it does not handle.

`create(legacyKey, hostProperties, display)` receives host `BlockBehaviour.Properties` and an original ambient display callback, not an original runtime object. It returns a `NativeBlock` containing the host replacement and metadata/state conversion functions. MFCL constructs no discarded placeholder Block (Forge would retain an unregistered intrusive holder). The registry ID and original item remain unchanged. Only original simple non-tile blocks may be replaced; duplicate replacements and invalid metadata round trips fail registration. Replacements must include an integer `legacy_meta` property covering 0..15 so existing saved states and generated models remain meaningful. Extra host properties are permitted.

`state(metadata)` returns the host state. `metadata(hostState)` maps it back to 0..15. Registration checks all 16 round trips. `update(previousState, metadata)` can retain host-only properties when original code changes metadata at a position. `placement(placementState, metadata)` can retain native placement behavior such as persistence and waterlogging. Both default to `state(metadata)`.

The native implementation owns its gameplay, drops and scheduled/random ticks. Its `DisplayTicks` callback can retain original ambient effects without creating an extra Block. Addons must use the public runtime APIs for original objects/items; no loader implementation types are part of this SPI. Host registry publication, original stack identity, the old-world block facade and original item placement continue through the generic MFCL bridge.
