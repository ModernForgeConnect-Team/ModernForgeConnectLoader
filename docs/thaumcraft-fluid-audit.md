# TC4 液体重新审查（2026-11-02）

样本为原始 Thaumcraft 4.2.3.5 与 Forge 1.7.10。以下区分原版代码、MFCL 桥接和实测范围，不能把储罐接口测试当成世界液体测试。

| 介质 | 原版行为 | 当前已知范围 |
| --- | --- | --- |
| 净化之水 | `BlockFluidClassic`；玩家碰到源方块、且尚无扭曲守卫时，消耗源方块并按永久扭曲计算效果时长。 | 沐浴盐、原版碰撞/扭曲守卫、自然流动和源桶取放均有验收。 |
| 死亡之水 | `BlockFluidFinite`；生物接触后按方块元数据加 1 计算溶解伤害。 | 已验证满液量的自然流动、桶取放及宿主生物碰撞伤害；不同液位伤害尚未逐级验收。 |
| 咒波粘浆 | `BlockFluidFinite`；接触时按液量减速并施加灵气衰竭，神秘史莱姆有吸收和成长的特殊分支。 | 已验证自然流动、宿主生物减速和灵气衰竭；对特殊原版实体类型、液量改变与成长未建立端到端证据。 |
| 咒波瓦斯 | `BlockFluidFinite`，原版密度方向向上；接触时按原版概率产生负面效果并减少瓦斯量。 | 已验证自然向上扩散及宿主生物随机效果；瓦斯消耗和所有随机结果尚未完整验收。 |
| 两种桶装液体 | TC4 的桶物品有各自的原版右键、放置和返回空桶逻辑。 | 已验证两种桶生存/创造取放及非液源拒绝；尚未覆盖所有手持、堆叠和网络时延场景。 |

调查时的关键缺口（以下首次流动触发已于随后修复）：Forge 旧版 `BlockFluidBase.onBlockAdded` 和邻居变化回调会安排首次流体更新。调查时镜像方块只有执行已安排更新的入口，没有转发这两个触发回调。调查时旧流体也没有被通用注册为现代 `FluidState`。随后已为液体材质提供原生状态和流体类型，并为旧储罐与已注册容器提供原生能力。液体 NBT、原版管道访问现代储罐的反向桥同样未完成。完整架构边界见 [流体桥状态](fluid-bridge-status.md)。

调查基线使用 `mfclDroppedItemFluidSmokeTest` 观察四种液体在加载区块、开放空气内的正常世界刻，并记录相邻扩散和现代 `FluidState`。该夹具随后扩展为验证修复后的流动、桶和接触效果。

修复前的调查结果：在一次性世界里，四种方块各自在开放空气中自然经过 200 刻后，六个相邻位置均没有同种方块，四个中心方块的现代 `FluidState` 也均为空。这些是修复前的观察，不表示修复后的当前状态。此实验覆盖放置后初始扩散，未覆盖所有邻居更新、碰撞、桶和设备路径。

## 后续修复

镜像的 Forge 旧液体现在在服务端放置及邻居发生变化时调用原方块回调，由原版自身安排和执行流动更新。空桶使用旧版液体射线和原始 `FillBucketEvent`，源方块判定及产出仍由 TC4 决定；服务端保留玩家权限和原生生存/创造物品交换。旧物品在创造模式改变世界但保留原物品时，原生使用结果也会标记为已处理。

`build/fluid-reaudit/game/logs/mfcl/dropped-item-fluid-smoke.json` 检查四种方块的初始竖向流动、移除阻挡后的流动、沐浴盐、纯净水与死亡水的空桶拾取及满桶倒出（生存/创造/非液源），并对真实宿主生物直接调用方块碰撞，检查死亡水伤害、粘浆减速与衰竭、瓦斯随机效果。最新报告 `status=PASS`；上述碰撞检查没有覆盖所有实体种类或每一种瓦斯随机结果。后续原生流体桥覆盖净化之水与死亡之水的液源、液位和生物浸入，并验证原生容器与 XU 储罐交互；咒波粘浆和瓦斯保留原方块行为，不冒充水类 `FluidState`。原版管道访问现代储罐及流体 NBT 转换仍未实现。
