# TC4 群系桥接

目标运行时：Forge 1.20.1 / Java 17，原始 Thaumcraft 4.2.3.5。不修改输入模组 JAR。

## 注册与读取

`ThaumcraftAdapter` 从原 `ThaumcraftWorldGenerator` 读取四个已创建的群系对象和配置权重，向 `LegacyBiomes` 声明稳定名称：

| 现代 ID | 原对象 | 主世界自然选择 |
| --- | --- | --- |
| `thaumcraft:magical_forest` | `biomeMagicalForest` | 由原 `biomeMagicalForestWeight` 控制 |
| `thaumcraft:tainted_land` | `biomeTaint` | 由原 `biomeTaintWeight` 控制 |
| `thaumcraft:eerie` | `biomeEerie` | 否，供显式改写使用 |
| `thaumcraft:eldritch` | `biomeEldritchLands` | 否，未创建邪术维度 |

生成资源包在动态注册表加载前提供 `worldgen/biome` 数据，使用原对象的温度、降水及草、叶、水、天空颜色。旧数字 ID 仅在旧对象域中使用，不写入现代区块。

宿主客户端、服务端和原方块渲染器的查询读取实际区块群系，再解析回对应的原对象；TC4 的对象比较与数字 ID 检查可继续使用。旧世界查询只接受 x/z，因此取该列地表高度处的群系。查询读取原始 quart 调色板，不采用现代视觉边界的 Voronoi 平滑。渲染查询使用所绘制方块高度。

现代原版群系通过显式表映射到 1.7.10 对象；有直接前身的群系保留其身份。樱花林、洞穴、新下界群系等使用表中指定的近似前身。这不是还原其完整现代生态；未知模组群系明确报映射缺失，不再无条件返回平原。

## 自然选择与存档

生成包扩展新世界的 `minecraft:normal`、`large_biomes`、`amplified` 预设，在原主世界多噪声来源外包裹 `mfcl:thaumcraft_biomes`。它保留原版来源，只在温和的平原、森林候选区，根据该世界的气候噪声选择魔法森林或腐化之地。两个权重为零时不改预设。

区域由世界种子和连续气候噪声决定，跨区块一致；权重决定选择带宽，不等同于 1.7.10 GenLayer 的精确分布或同种子坐标。来源使用注册 codec 序列化，重开世界沿用相同配置和分布。超平坦、单群系世界、下界和末地不包裹。用户数据包若覆盖相同预设，最终采用数据包优先级决定的预设。

已有存档仍使用其中保存的生成器，不自动换生成器或改写旧区块；其原版生成器也不会仅因安装此修复而在后续新区块产生 TC4 群系。测试自然生成应新建普通世界。已有世界可用现代 `/fillbiome` 指定这些已注册 ID，或由已桥接的原 TC4 改写入口修改群系。

## 群系改写

TC4 的 `Utils.setBiomeAt(World,x,z,BiomeGenBase)` 原先直接修改旧区块的 `byte[256]`。专属字节码适配器只替换这一方法，转发到拥有线程上的宿主世界；其他原方法继续执行。写入现代区块群系调色板、标记保存，并通过原生区块群系包同步跟踪该区块的玩家。客户端不能通过该入口修改权威群系。

1.20.1 群系存储的水平分辨率为 4×4，因此一次旧版单列改写作用于包含该列的 4×4 区域及全部垂直区段。相邻 quart 列保持原值，负坐标按向下取整处理。此项差异无法通过把旧数字 ID 放入现代数组来消除。

## 当前边界与验证

本轮接通群系注册、身份查询、基本自然选择、颜色、显式改写、网络同步和持久化。现代群系暂用原版森林/平原的地形装饰模板；原 TC4 的特殊树木、植物装饰、节点、遗迹和自定义生物生成尚未桥接。腐化传播、银树净化等完整机制也不能仅凭其底层群系改写入口可用就视为已通过验收。

`RuntimeBiomeProbe` 在实际旧运行时验证不同原版群系身份、坐标传递和未知映射拒绝；带 TC4 样本的集成测试还执行原 `Utils.setBiomeAt`、四种群系往返、空对象与客户端写入拒绝。

`-PmfclBiomeSmokeTest` 自动创建普通世界，检查现代注册表及原颜色、两种自然生成区块、原改写入口、负坐标与邻列、客户端查询/同步、渲染视图和磁盘重载。结果写入隔离游戏目录 `logs/mfcl/biome-smoke.json`。
