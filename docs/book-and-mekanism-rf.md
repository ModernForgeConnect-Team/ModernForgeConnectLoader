# 魔导手册与 Mekanism RF 回归修复（2026-10-22）

## 修复

便携容器捕获此前无条件吞掉客户端 `EntityPlayer.openGui`。Thaumcraft 的魔导手册是客户端独立界面，不提供服务器容器，因此右键没有界面可打开。现在调用原始 GUI handler：容器界面仍等待宿主服务器开窗，非容器界面进入原有客户端屏幕捕获和重放流程。

Extra Utilities `TNHelper.getPipe` 在读取管道前硬编码拒绝 Y<0 或 Y>=256。新版世界负高度下，发电机可以把 RF 推入节点，但节点无法查询管道并继续寻路。私有适配器只替换这个高度/可访问性检查，调用宿主世界的有效且已加载位置判断，保留其余原始管道和能量算法。未绑定宿主的旧世界保留 0..255 限制，不修改原始 JAR，也不加载远处区块。

## 实际验收

Java 17、Forge 1.20.1-47.4.28、Baubles 1.0.1.10、Thaumcraft 4.2.3.5、Extra Utilities 1.2.12，以及真实 Mekanism 1.20.1-10.4.16.80。使用独立临时平坦世界，在负高度由正常服务器方块 tick 执行传输，接收端为实际基础能量单元西侧输入口。

| 连接 | 接收 FE | 源端剩余 RF | 节点剩余 RF |
| --- | ---: | ---: | ---: |
| 发电机 → Mek 能量单元 | 10000 | 0 | — |
| 发电机 → 能量节点 → Mek 能量单元 | 10000 | 0 | 0 |
| 发电机 → 能量节点 → 两节传输管道 → Mek 能量单元 | 10000 | 0 | 0 |

三个场景均从 10000 RF 开始，无额外燃料，设备 tick 未暂停，能量守恒。发电机直连输入口在修复前也能工作；复现的卡点是负高度节点寻路。保留 Mekanism 的输入/输出面限制，未强制向输出面灌能。

原始管道回归还检查 Y=-64、-60、0、64、255、256、319，以及越界和未加载位置。

开发测试入口为 `-PmfclMekanismEnergySmokeTest '-PmekanismTestVersion=10.4.16.80'`。后者仅给测试运行添加反混淆的真实 Mekanism 依赖，不成为普通 MFCL 构建的必需模组。测试写入 `logs/mfcl/mekanism-energy-smoke.json`，随后执行魔导手册的原生右键、条目、分类、研究同步和重开验收，写入 `logs/mfcl/book-smoke.json`。

最终两份原生报告均为 PASS，`assemble` 成功。全量回归仍为 123 项中 116 通过、6 跳过、1 失败；失败是此前已记录的研究台非法操作用例，未在本批修复。新 JAR 为 `build/libs/mfcl-0.2.8.jar`，需完全重启游戏加载。
