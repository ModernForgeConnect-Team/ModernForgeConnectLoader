# Modern Forge Connect Loader

[English](../README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [Русский](README.ru.md) · [Deutsch](README.de.md) · [한국어](README.ko.md)

Modern Forge Connect Loader (MFCL) — экспериментальная среда совместимости для запуска оригинальных модов Forge 1.7.10 внутри хоста Forge 1.20.1 / Java 17.

## Назначение и принципы проектирования

MFCL выполняет настоящий старый FML и исходный код модов в изолированной области загрузки классов той же JVM. Мосты связывают поддерживаемые игровые объекты, реестры, отрисовку и взаимодействия с современной игрой. Оригинальные JAR-файлы модов остаются неизменными.

Ядро предоставляет общие механизмы, а поведение конкретных модов относится к необязательным адаптерам. Система знаний Thaumcraft и динамическая отрисовка таумометра постепенно выделяются в слой совместимости TC4. Developer API / MFCL Legacy Accessor (MLA) позволяет современным дополнениям вызывать старый код без зависимости от старых классов Minecraft при компиляции.

**Проект находится в разработке. Успешная инициализация или видимый предмет не означают полной совместимости игровой логики.**

## Требования и установка

| Компонент | Текущая целевая версия |
| --- | --- |
| Хост | Minecraft 1.20.1, Forge 47.4.28 |
| Java | JDK 17 |
| Старая среда | Minecraft 1.7.10, Forge 10.13.4.1614; отдельно подготовленная среда с именами SRG |
| Проверенная графическая среда | Windows 11; клиент и встроенный сервер |

1. Соберите MFCL с Java 17 или используйте соответствующую сборку. Поместите полный `mfcl-0.1.0.jar` в каталог `mods/` современной игры.
2. Получите оригинальные старые моды и обязательные зависимости. Разместите их непосредственно в `mods/1.7.10/`, а не в корневом каталоге современных модов.
3. Подготовьте старую среду и манифест проверенных входных файлов. См. [среду тестирования и подготовку](../docs/testing.md). JAR MFCL и Dependency Resolver не содержат полную старую среду Minecraft и не устанавливают её автоматически.
4. Запустите Forge. Проверьте `logs/mfcl/legacy-1.7.10.json` и `logs/mfcl/runtime-1.7.10.json`: обнаружение файлов, реальные этапы загрузки и ошибки.

```text
<game-directory>/
  mods/
    mfcl-0.1.0.jar
    1.7.10/
      original-mod.jar
      required-legacy-dependency.jar
  mfcl/runtime/1.7.10/
    runtime-manifest.json
    minecraft-forge-1.7.10-srg.jar
    ...
```

MFCL использует каталог самой игры и проверяет только JAR непосредственно внутри `mods/1.7.10/`. Оригинальные файлы Minecraft, Forge и сторонних модов не распространяются вместе с MFCL.

## Реализованные возможности совместимости

- Настоящая инициализация старого FML, поддерживаемые трансформеры CoreMod и Access Transformer в изолированной области.
- Регистрация современных представителей предметов и блоков, сохранение metadata и оригинального NBT, генерация текстур и переводов, поддерживаемые установка, выпадение и сохранение.
- Поддерживаемая отрисовка старых GUI, шрифтов, предметов, блоков и блочных сущностей; отдельные динамические предметы и старые звуки.
- Частичные мосты для мира, состояния игроков, инвентаря, редстоуна, логики блочных сущностей и поддерживаемых обычных рецептов верстака.
- Экспериментальный Developer API / MLA, явные преобразования объектов, диагностика и отдельный инструмент зависимостей.

| Эталонный мод | Проверенный объём |
| --- | --- |
| NotEnoughItems 1.0.5.120 и зависимости CodeChicken | Реальная инициализация, панель рядом с инвентарём, поиск, оригинальные страницы рецептов и применений |
| AcademyCraft 1.0.7 и LambdaLib 1.2.3 | Реальная инициализация, базовая регистрация содержимого, отдельные проверки установки и сохранения |
| Thaumcraft 4.2.3.5 и Baubles 1.0.1.10 | Реальная инициализация, отдельные мосты отрисовки и игровой логики, Таумономикон, сканирование с удержанием, награды, сохранение и звуки |

[Указатель технической документации](../docs/README.md) содержит подробные границы поддержки, хэши оригинальных файлов и датированные результаты приёмочных проверок. Результаты относятся к проверенным версиям и функциям.

## Ограничения совместимости

MFCL пока не является полным клиентом Forge 1.7.10, универсальным эмулятором OpenGL или заменой всех старых игровых подсистем. Произвольные моды, собственные GUI и рендереры, машины, генерация мира, сущности, способности игроков и сетевые протоколы поддерживаются частично либо ещё не реализованы. Проверки встроенного сервера не подтверждают совместимость выделенного сервера.

Неподдерживаемые преобразования и преобразования с потерей данных явно отклоняются. У современных блоков и предметов может не быть старого представления. Общая передача событий и преобразование сущностей / игроков ещё не завершены. Поддержка обычного верстака не означает поддержку магического верстака, тигля, наполнения и других специальных систем крафта.

Проверка завершения сканирования TC4 и перехват пакета сканирования пока используют специальные пути совместимости. План переноса описан в [руководстве API и границах адаптеров](../docs/developer-api.md). Старые контейнеры остаются в старом FML: объединённый список модов не означает их регистрацию в современном ModList или сетевом рукопожатии.

## Пример Developer API / MLA

Используйте отдельный API с `compileOnly`. Не включайте его в JAR дополнения и не добавляйте старые классы Minecraft в современный runtime classpath.

```groovy
dependencies {
    compileOnly files('libs/mfcl-0.1.0-api.jar')
}
```

Объявите открытый accessor в дополнении и подпишитесь при инициализации:

```java
@LegacyType("net.minecraft.item.ItemStack")
public interface OldStack {
    @LegacyMethod(name = "func_77946_l",
                  descriptor = "()Lnet/minecraft/item/ItemStack;")
    LegacyObject copy();
}

MfclApi.whenReady(runtime -> {
    LegacyObject stack = runtime.stack(
        new LegacyStack("minecraft:diamond", 0, 2, ""));
    LegacyObject copy = runtime.accessor(OldStack.class, stack).copy();
});
```

MLA использует точные старые имена SRG и дескрипторы JVM. Старые ссылки непрозрачны и принадлежат одной среде; игровую логику следует вызывать в соответствующем игровом потоке. Импорты, поля, конструкторы, преобразования, жизненный цикл и ограничения описаны в [компилируемом примере](../examples/legacy-accessor/) и [руководстве API](../docs/developer-api.md). Команда `/mfclapi` предоставляет диагностику для администратора.

## Legacy Dependency Resolver

[Отдельный плагин Gradle](../tools/legacy-dependency-resolver/) использует разрешение зависимостей Gradle и явно заданный импорт локальных JAR. Требуются фиксированный SHA-256, источник и сведения о лицензии / распространении. Инструмент не добавляет удалённые репозитории, не разрешает транзитивные зависимости и не устанавливает старые JAR в современный runtime classpath.

Результат — JAR с адресацией по содержимому и манифест происхождения. Настройка, поведение при ошибках и тесты описаны в [README инструмента](../tools/legacy-dependency-resolver/README.md).

## Сборка, тестирование и участие

Выполняйте из корня репозитория с JDK 17:

```powershell
.\gradlew.bat test build
.\gradlew.bat apiJar apiSourcesJar compileApiExample
.\gradlew.bat -p tools/legacy-dependency-resolver test validatePlugins
.\gradlew.bat inspectLegacyMods "-PlegacyGameDir=C:/path/to/game"
```

Полный мод и API записываются в `build/libs/`. Вне Windows используйте `./gradlew`. Проверки, требующие отсутствующих внешних файлов, пропускаются; графическая приёмка требует подготовленного игрового каталога. Подготовка, флаги smoke-тестов и изолированные выходные каталоги описаны в [тестировании и воспроизводимости](../docs/testing.md).

При участии указывайте мод и версию, шаги воспроизведения, логи и ожидаемое поведение. Общие механизмы размещайте в ядре, специфичную логику — в адаптерах. Прилагайте целевые регрессионные проверки, сохраняйте оригинальные JAR и соблюдайте существующие правила потоков, владения объектами и регистрации.
